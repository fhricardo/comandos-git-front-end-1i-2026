Guia de Comandos Git para gerenciamento de repositórios

Neste documento, temos a listage mdos principais comandos Git para gerenciamento de repositórios e configurações necessárias para correta utilização do controle de versionamento, incluindo padrões de commits.

Comandos de Configuração

Para configurar o nome de usuário do Github no Git:

git config --global user.name "nome_de_usuario"

Para configurar o e-mail de usuário do Github no Git:

git config --global user.email "seu_email@dominio.com"

Para configurar "main" como nome padrão da branch principal para novos repositórios:

git config --global init.defaultBranch main

Para verificar as credenciais ativas:

git config --global --list

Trabalhando com repositórios

Para inicializar um repositório no diretório atual:

git init

Para adicionar o endereço do repositório remoto:

git remote add origin endereço_do_repositiorio_remoto.git

Para adicionar todos os arquivos do diretório atual (incluindo subpastas) ao repositório local:

git add .

Para adicionar uma commit1:

git commit -m "texto descritivo da commit"

1 Confira abaixo as boas práticas para criação de commits.

Para enviar o conteúdo do repositório local para o repositório remoto:

git push origin <nome_da_branch>

Ex.: git push origin main

Para verificar o status do repositório:

git status

Para copiar um repositório remot para o seu computador:

git clone endereço_do_repositiorio_remoto.git

Para puxar alterações existentes em um repositório remoto:

git pull origin <nome_da_branch>

Ex.: git pull origin main

Verificar qual a branch atual:

git branch

Boas prátias em nomenclatura de commits

O padrão mais utilizado no mercado hoje é o Conventional Commits. Ele estabelece uma estrutura simples para tornar o histórico de commits legível tanto para pessoas quanto para ferramentas de automação (como geração automática de changelogs e versionamento semântico).

Tipo Quando Usar Exemplo
feat Nova funcionalidade (feature) feat(auth): adiciona login com Google
docs Alterações na documentação docs(readme): atualiza instruções de instalação
fix Correção de um bug fix(checkout): corrige cálculo do frete com cupom
style Formatação de código (espaços, vírgulas) sem alterar lógica style(lint): aplica regras do ESLint no controller
refactor Mudança no código que não corrige bug nem adiciona funcionalidade refactor(user): simplifica validação de e-mail
perf Mudança que melhora a performance perf(db): adiciona índice na tabela de pedidos
ci Alterações em arquivos de CI/CD (GitHub Actions, GitLab CI) ci(deploy): ajusta pipeline de staging
chore Tarefas de manutenção, build ou atualização de dependências chore(deps): atualiza pacote axios para v1.6.0
test Criação ou ajuste de testes unitários/integração test(cart): adiciona testes unitários para desconto
build Mudanças no sistema de build ou scripts externos build(webpack): otimiza minificação do bundle
